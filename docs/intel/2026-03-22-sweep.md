## HIGH RELEVANCE — Directly affects Klatch

### 1. Web Search + Code Execution — GA with Dynamic Filtering

Web search and code execution tools are now generally available (no beta header required). The big addition: **dynamic filtering** — Claude can write and run Python code to post-process search results before they reach the context window, keeping only relevant information.

Performance: 11% average accuracy improvement while using 24% fewer input tokens. Opus 4.6 hit 77.3% on DeepsearchQA F1 (up from 69.8%). Code execution is **free** when used with web search or web fetch.

**Why it matters for Klatch:** If Klatch entities gain tool-use capabilities (Agent SDK path), web search with dynamic filtering is the mechanism for entities that can research and bring back only what's relevant. Also relevant to the intelligence sweep itself — a Klatch entity could be configured to run daily sweeps autonomously. The "free code execution with web search" pricing removes a cost barrier.

**Source:** [Platform Docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool), [Gend.co analysis](https://www.gend.co/blog/claude-web-search-dynamic-filtering)

### 2. Claude Code Agent Teams — Experimental Multi-Agent Orchestration

Claude Code now has a built-in **Agent Teams** feature: one session acts as team lead, coordinating up to 10 specialized sub-agents working in parallel. Teammates work independently in their own context windows and communicate via structured message passing. Unlike subagents (which report only to the parent), you can interact with individual teammates directly.

Requires `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` in settings. Opus 4.6 access required. Cuts wall-clock time 3-5x on parallelizable work but costs proportionally more tokens.

**Why it matters for Klatch:** This is the most direct convergence signal yet with Klatch's multi-entity roundtable model. Key differences: Agent Teams are session-scoped (no persistence), terminal-centric (not web UI), and oriented toward code tasks (not general conversation). But the architectural pattern — lead agent coordinating specialists with message passing — mirrors Klatch's design. Watch closely for: persistence, conversation history, and non-code use cases. Those would be direct competitive overlap.

Also: our own team workflow (Daedalus, Argus, Theseus, Calliope) could potentially use Agent Teams for coordinated work sessions, though our async mailbox model is better suited to cross-session coordination.

**Source:** [Claude Code Docs](https://code.claude.com/docs/en/agent-teams), [Claudefast Guide](https://claudefa.st/blog/guide/agents/agent-teams)

### 3. Models API Capability Discovery (March 19)

`GET /v1/models` and `GET /v1/models/{model_id}` now return `max_input_tokens`, `max_tokens`, and a `capabilities` object describing what each model supports.

**Why it matters for Klatch:** Klatch's entity model selector currently hardcodes model capabilities. With this API, we could dynamically query available models and their capabilities at startup, future-proofing against model additions and deprecations. The entity creation UI could show actual limits instead of static values.

**Source:** [Platform Release Notes](https://platform.claude.com/docs/en/release-notes/overview)

### 4. Extended Thinking Display Field — Omit Thinking Content

New `thinking.display: "omitted"` option lets you receive thinking blocks with empty content but preserved signatures for multi-turn continuity. Streaming is faster because thinking content isn't transmitted.

**Why it matters for Klatch:** Our streaming bridge in `client.ts` currently processes thinking blocks. If we don't display thinking to users (or only display it on request), omitting thinking content would reduce bandwidth and speed up streaming in roundtables — especially in multi-entity conversations where multiple responses stream sequentially. The signature preservation means we keep multi-turn coherence without the display overhead.

**Source:** [Platform Release Notes](https://platform.claude.com/docs/en/release-notes/overview)

### 5. Claude Code v2.1.81 — Bare Mode and Channels Permission Relay

Latest Claude Code release (March 20/21) adds:
- **`--bare` flag:** Strips hooks, LSP, plugin sync, and skill directories for scripted `-p` calls. Auto-memory disabled. Requires direct API key (no OAuth/keychain).
- **`--channels` permission relay:** Channel servers can forward tool approval prompts to your phone.
- **Fixes:** Concurrent OAuth sessions no longer fight over tokens. Background agent task race condition resolved.

**Why it matters for Klatch:** The `--bare` flag is relevant if Klatch ever orchestrates Claude Code sessions programmatically (via Agent SDK or direct CLI). Bare mode removes overhead that's irrelevant for API-driven use. The concurrent OAuth fix is relevant to multi-agent workflows where multiple Claude Code sessions run simultaneously — exactly our team setup.

**Source:** [GitHub Releases](https://github.com/anthropics/claude-code/releases), [Changelog](https://code.claude.com/docs/en/changelog)

## Synthesis: What this means for Klatch

**The multi-agent convergence is real and accelerating.** Since the last sweep two days ago, the biggest development isn't any single feature — it's the pattern. Claude Code Agent Teams, Cursor's 8-agent interface, Windsurf's parallel Cascades, and Copilot's issue-to-PR agent all shipped or matured in the same window. Every major tool now treats multi-agent orchestration as table stakes. Klatch's positioning as a *conversation-centric* multi-entity system (vs. code-centric multi-agent) remains distinct, but the window for that distinction is worth monitoring.

**The API is handing us gifts.** Three features from this sweep directly reduce complexity in Klatch's codebase:
1. **Models API capabilities** → replace hardcoded model info with dynamic discovery
2. **Thinking display omission** → faster streaming in roundtables without losing multi-turn coherence
3. **Web search + code execution GA** → enables research-capable entities without building our own search infrastructure

**Alignment research is converging with our methodology.** AuditBench's approach (implant known behaviors, test detection) is structurally parallel to AXT (implant known context, test retention). This is independent validation that systematic testing of AI system state is a research-worthy problem, not just a QA concern.
