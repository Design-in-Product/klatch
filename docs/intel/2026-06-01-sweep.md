### 3. NSA MCP Security Advisory (May 20) — First government threat model for MCP deployments

The NSA Artificial Intelligence Security Center released "Model Context Protocol: Security Design Considerations for AI-Driven Automation" on May 20, 2026. Key findings: authentication is optional and absent in many implementations; no RBAC defined at protocol level; OAuth-style bearer token lifecycle left entirely to implementers; tool parameter injection (unsanitized params → arbitrary command execution); serialization risks; implicit trust relationships across agents. Government contractors must apply NSA MCP security design controls (context labeling, cryptographic isolation, least privilege interfaces, audit logging) by September 30, 2026.

**Source:** https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4496698/nsa-releases-security-design-considerations-for-ai-driven-automation-leveraging/
**Klatch impact:** Klatch's MCP server uses `StdioServerTransport` (local stdio, not HTTP). The bearer token / OAuth vulnerability class does NOT apply to stdio transport. The OX Security STDIO injection class (tool parameter injection) is the most applicable concern — worth a targeted read of `packages/server/src/mcp/server.ts` to audit tool parameter handling. Klatch's channel-boundary isolation (verified in Round 27b) addresses context sharing concerns at the application layer. **Prior mentions:** OX Security STDIO injection covered in `docs/intel/2026-05-11-sweep.md` (Klatch concluded not exposed as server-side).
