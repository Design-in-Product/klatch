## HIGH RELEVANCE

### 1. Sonnet 5 Tokenizer +30% — Compaction Budget Impact

Claude Sonnet 5 (June 30) ships a new tokenizer that produces approximately 30% more tokens from the same input text compared to Sonnet 4.6. This is separate from the model being added to the picker (already done). The compaction impact is a distinct, unactioned concern.

Klatch's compaction threshold is 160K tokens, tuned during Step 9 for 1M-context models (see `docs/research/compaction-threshold-deep-dive.md`). Users running Sonnet 5 as their entity model will hit this threshold sooner — the same conversation reaches 160K in ~77% as many turns as on Sonnet 4.6. This also raises per-session cost ~30% for Sonnet 5 users at the same usage pattern.

Sonnet 5 is now the default for Free and Pro Claude.ai users; as Klatch users start picking it, the threshold will matter more.

**Source:** https://www.anthropic.com/news/claude-sonnet-5
**Klatch impact:** Compaction threshold (160K) and cost estimates in kit briefing / Step 10.5 persona capture may need recalibration for Sonnet 5 users. Worth Argus's evaluation — no code change required immediately but should be noted before Step 11 design, which depends on the memory architecture.
**Prior mentions:** Tokenizer issue tracked for Opus 4.7 (+35%) in `docs/mail/read/argus-to-daedalus-opus-4-7-impact-2026-04-29.md`. Compaction threshold research in `docs/research/compaction-threshold-deep-dive.md`. Sonnet 5 itself is fresh this window.
**Verified against:** `packages/server/src/claude/client.ts` — compaction threshold is applied in streaming logic. Tokenizer delta affects token-count-based gating; no API surface mismatch.

### 3. MCP Spec 2026-07-28 RC — Beta SDKs Published; Final in 22 Days

The MCP 2026-07-28 release candidate is now in its final validation window. Beta SDKs for the RC shipped this week. Final spec: July 28 (22 days). Key changes: stateless protocol core (no session handshake, any request can hit any server instance); new `Mcp-Method` and `Mcp-Name` transport headers; `ttlMs` + `cacheScope` on list/resource results; Tasks extension (long-running work); MCP Apps extension (server-rendered UIs).

The headline "stateless" change affects Streamable HTTP transport servers. Klatch is stdio-only for 1.0.

**Source:** https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
**Klatch impact:** No change required before July 28 — Klatch's stdio transport is unaffected by the stateless HTTP change. Worth Argus noting the Tasks extension (long-running work) as relevant to Klatch's "standing workflow templates" and "Workflows" vision items. If Klatch ever adds HTTP transport, the stateless model simplifies scale-out significantly.
**Prior mentions:** MCP 2026-07-28 spec RC first tracked in `docs/intel/2026-06-22-sweep.md`. "Stateless" appears in many earlier sweeps in different contexts. Beta SDKs are fresh this week.
**Verified against:** `packages/server/src/mcp/bin.ts:13` (StdioServerTransport) — Klatch is stdio-only; stateless HTTP change is N/A for 1.0.
