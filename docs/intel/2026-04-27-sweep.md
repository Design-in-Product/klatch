## HIGH RELEVANCE

### 1. Claude Opus 4.7 GA — thinking omitted by default (API behavior change)

Released April 16, now two weeks old. The 4/26 curated sweep noted it as "evaluate, defer 1–2 weeks." This sweep surfaces two technical changes not called out in that sweep:

**Thinking content now omitted by default.** Starting with Opus 4.7, `thinking` blocks still appear in the streaming response but their `thinking` field is **empty** unless the caller opts in with `betas: ["thinking-summaries-2025-02-19"]` or equivalent. This is a **breaking behavioral change** for Klatch's artifact capture: `message_artifacts` stores thinking blocks; if Klatch does not opt in, the stored thinking content will be blank for any Opus 4.7 channel.

**New tokenizer (+1x–1.35x tokens).** Opus 4.7 uses a new tokenizer that produces 1x–1.35x as many tokens as prior models on equivalent input. This directly affects Klatch's token discipline (Design Principle 7), compaction thresholds (already tuned to 160K in Round 17), and any cost estimates surfaced to the user. Channels running Opus 4.7 as their entity model will silently see higher token consumption and API costs.

**Source:** https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-7 / https://www.anthropic.com/news/claude-opus-4-7
**Klatch impact:** Two action items — (a) audit whether Klatch explicitly opts in to thinking content for Opus 4.7 calls; (b) flag tokenizer cost change in the channel stats UI or documentation.

### 2. Opus 4.7 — new effort level `xhigh` and task budgets

Opus 4.7 introduces a new `xhigh` effort level between `high` and `max`. Claude Code defaults to `xhigh` for coding workflows after 4.7. Klatch's Round 17 work added per-entity effort parameters with model-aware defaults (Sonnet → medium, others → high). The `xhigh` value is not yet in Klatch's effort enum; any entity channel that should leverage Opus 4.7's full capability would need it added.

Task budgets are also new: callers can pass a rough token target for a full agentic loop, with the model using a countdown to finish gracefully. This is relevant to Klatch's long-form multi-entity roundtables, where budget-aware finishing could improve response quality under compaction pressure.

**Source:** https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-7
**Klatch impact:** Add `xhigh` to the effort enum; evaluate task budgets as an optional parameter in the entity/channel settings.

## MEDIUM RELEVANCE

### 3. MCP STDIO design vulnerability — Anthropic declines to patch

Ox Security published a detailed disclosure (April 15) of what they call an architectural design flaw in the MCP STDIO interface: the `subprocess.exec` call in the official MCP SDKs (Python, TypeScript, Java, Rust) fires regardless of whether the subprocess starts successfully, enabling arbitrary command injection by passing a malicious server command. They estimate 200K vulnerable instances, 150M downloads affected. Anthropic confirmed the behavior is intentional and declined to patch, placing sanitization responsibility on developers.

The 4/26 sweep noted MCP security coverage as LOW (trade press framing only). Now that the Ox Security technical report is public and Anthropic's position is confirmed, this deserves MEDIUM attention:

Klatch's MCP server uses STDIO and is single-user local-only — the typical attack surface (remote untrusted servers) is absent. But if a future Phase 5d adds HTTP transport or multi-user mode, the pattern matters. Also: if Klatch ever dynamically constructs the MCP server invocation string from user input, that's the injection vector.

**Source:** https://www.ox.security/blog/the-mother-of-all-ai-supply-chains-critical-systemic-vulnerability-at-the-core-of-the-mcp / https://www.theregister.com/2026/04/16/anthropic_mcp_design_flaw/
**Klatch impact:** Verify `packages/server/src/mcp/bin.ts` does not take user-controlled input in the server command path. File a note for Phase 5d design.
