## MEDIUM RELEVANCE

### 3. Claude Code 2.1.166 — SendMessage Authority Hardening (June 6)

Claude Code 2.1.166 (June 6) ships a security hardening: messages relayed via `SendMessage` from other Claude sessions **no longer carry user authority**. Receivers refuse relayed permission requests; auto mode blocks them. This prevents a lower-privileged session from tricking another session into granting elevated permissions via a relayed message.

Also in 2.1.166: `fallbackModel` setting (up to 3 fallback models tried in order on overload/error); glob pattern support in deny rules (`"*"` denies all tools); `MAX_THINKING_TOKENS=0` / `--thinking disabled` now works on Claude API models that think by default.

**Source:** https://code.claude.com/docs/en/changelog
**Klatch impact:** Klatch's agent team (Daedalus, Argus, Theseus, Calliope, etc.) all run in Claude Code sessions. If any agents use `SendMessage` for cross-session coordination, they can no longer obtain elevated permissions via relayed messages — this is the right behavior and likely non-breaking for Klatch's mail-based (filesystem memo) coordination model. Argus should verify: do any Klatch agent sessions use `SendMessage` for permission escalation? The `fallbackModel` setting is relevant for Klatch agent sessions running long tasks with Opus 4.7/4.8 (model overload fallback to Sonnet). The thinking-disable flag is relevant to AAXT probing where extended thinking is specifically turned off to probe baseline behavior.
**Prior mentions:** SendMessage mentioned in `docs/intel/2026-03-22-sweep.md`, `docs/intel/2026-04-13-sweep.md`, `docs/intel/2026-05-04-sweep.md` (as a multi-agent feature, not security context). Frame as new security hardening delta; `fallbackModel` is a fresh find with no prior mentions in repo.
