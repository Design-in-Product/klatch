### 4. MCP STDIO command injection (OX Security advisory, April–May)

OX Security published CVE advisories covering a command-injection design flaw in the MCP SDK's STDIO transport: unsanitized OS commands passed to STDIO server constructors execute before the connection error returns. A second attack vector allows prompt injection to poison an MCP client's configuration and auto-register a malicious STDIO server. Over 150 million downloads affected; only 3 of 11+ CVEs patched as of May 11.

Separately, CVE-2026-33032 (CVSS 9.8) in the nginx-ui MCP endpoint (a third-party nginx management tool) allows unauthenticated full server takeover via missing auth middleware. Actively exploited in the wild; patched in nginx-ui 2.3.4.

**Source:** https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem/ / https://pluto.security/blog/mcp-bug-nginx-security-vulnerability-cvss-9-8/
**Klatch impact:** **Klatch is not directly exposed.** Klatch runs as an HTTP/SSE MCP server — it does not use STDIO transport and does not spawn subprocesses in response to tool calls. CVE-2026-33032 is specific to nginx-ui (Klatch does not use nginx-ui). However: (a) Klatch users who connect via Claude Code as an MCP client *are* potentially exposed client-side if they run other STDIO-based MCP servers; (b) `docs/MCP-SETUP.md` should include an explicit security posture note explaining that Klatch's HTTP-based transport sidesteps the STDIO injection class. Low priority but warranted for user trust.
