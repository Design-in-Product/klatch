## HIGH RELEVANCE — Directly affects Klatch

### 1. Cowork Projects — Import from Claude.ai, Local Folder Binding (March 20)

**Relevance: 3 — Strategic alignment opportunity**

Anthropic shipped Projects for Cowork on March 20. The key features:

- **Import from Claude.ai Projects:** One-click import of an existing Claude.ai project (files + instructions) into a new Cowork project. Each Cowork project is backed by a local folder.
- **Local folder binding:** Projects can attach to an existing local folder or create a new one. Files and instructions stay on the user's machine.
- **Project-scoped memory:** Claude remembers context within a project across tasks. Memory is scoped — doesn't leak between projects.
- **Scheduled tasks integration:** Scheduled tasks (shipped Feb 25) now bind to project scope for repeatable workflows.

This creates **three distinct project models** in the Anthropic ecosystem:

| Surface | Project model | Storage | Persistence | Memory |
|---------|--------------|---------|-------------|--------|
| Claude.ai | Cloud projects | Cloud (Anthropic servers) | Permanent | Project knowledge base |
| Claude Code | Repository (CLAUDE.md) | Local git repo | Git history | CLAUDE.md + session memory |
| Cowork | Local folder projects | Local filesystem | Local + optional sync | Project-scoped memory |

**Import paths currently supported:**
- Claude.ai → Cowork (one-click import, shipped)
- Local folder → Cowork (folder binding, shipped)
- Claude Code ↔ Cowork (shared folder + CLAUDE.md, manual but functional)
- Claude.ai → Claude Code (not supported)

**What's NOT connected:** Claude Code has no "Projects" feature yet. Anthropic says it's planned. There's no cloud sync for Cowork project data. The Claude.ai → Claude Code path doesn't exist. A GitHub feature request (#25833) asks for Claude Code and Cowork to access Claude Chat Project knowledge bases — still open.

**Why it matters for Klatch:** Klatch is building its own project model (the `projects` table with instructions, memory, and source metadata). We now have three Anthropic project models to study and potentially align with. The import gap — Claude.ai projects can reach Cowork but NOT Claude Code — is exactly the kind of portability problem Klatch already solves for conversations. If Klatch can import from all three surfaces and provide a unified project view, that's a significant differentiator.

The project-scoped memory in Cowork is architecturally similar to our `projects.memory` field. Worth studying whether their memory format is exportable.

**Source:** [Claude Help Center](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-cowork), [Cybersecurity News](https://cybersecuritynews.com/projects-feature-claude-cowork-desktop/), [MLQ](https://mlq.ai/news/anthropic-rolls-out-projects-feature-for-claude-cowork-desktop/)

### 2. Claude Sonnet 4.6 — New Default Model (February 17, now broadly deployed)

**Relevance: 3 — Direct impact on Klatch entity model selector**

Sonnet 4.6 is now the default model on Free and Pro plans. Key stats:
- **Performance:** SWE-bench 79.6%, 30-50% latency reduction vs Sonnet 4.5
- **1M context window** (beta)
- **Adaptive thinking** (recommended mode for both Opus 4.6 and Sonnet 4.6)
- **Pricing:** Same as Sonnet 4.5 ($3/$15 per million tokens)
- **Compaction:** Server-side context summarization for effectively infinite conversations
- **Prompt injection resistance:** Major improvement over Sonnet 4.5, comparable to Opus 4.6

**Why it matters for Klatch:** Klatch's entity model selector needs updating. Sonnet 4.6 should be offered as a cost-effective entity option. The compaction API is directly relevant — Klatch's long conversations could benefit from server-side summarization instead of client-side truncation. The 1M context window for both Opus 4.6 and Sonnet 4.6 means our token budget calculations may need revisiting.

**Source:** [Anthropic announcement](https://www.anthropic.com/news/claude-sonnet-4-6), [Platform docs](https://platform.claude.com/docs/en/about-claude/models/whats-new-claude-4-6)

### 3. Claude Code Review — Multi-Agent PR Review System (March 9-10)

**Relevance: 2 — Architectural pattern validation**

Anthropic launched Code Review: a managed PR reviewer that dispatches multiple agents in parallel, cross-verifies findings, and posts ranked issues to GitHub. This is the system Anthropic runs on nearly every internal PR.

Key details:
- Multiple agents work in parallel per PR, scaling with PR size
- Cross-verification between agents filters false positives
- Before: 16% of PRs got substantive comments. After: 54%
- Less than 1% of findings marked incorrect by engineers
- ~20 minutes per review, $15-25 per review
- Uses `REVIEW.md` (alongside `CLAUDE.md`) for project-specific review instructions
- Available for Team and Enterprise plans

**Why it matters for Klatch:** The multi-agent parallel review pattern (dispatch N agents → cross-verify → synthesize) is a validated production architecture for multi-entity coordination. This is architecturally similar to what a Klatch roundtable could do — multiple entities analyzing the same input, with a synthesis step. The `REVIEW.md` convention is also interesting as a parallel to our per-project instructions.

**Source:** [Claude blog](https://claude.com/blog/code-review), [TechCrunch](https://techcrunch.com/2026/03/09/anthropic-launches-code-review-tool-to-check-flood-of-ai-generated-code/)

## Synthesis: What this means for Klatch

**The three-project-model opportunity is real.** Anthropic now has three distinct project surfaces (Claude.ai, Claude Code, Cowork), each with its own storage model, memory model, and persistence model. They're connected by thin import paths (Claude.ai → Cowork, shared folder for Code ↔ Cowork), but there's no unified view. This is the same pattern we saw with conversations — multiple surfaces, fragmented history, no portable format. Klatch already solved this for conversations with the import pipeline. Extending that to projects (importing project context, memory, and instructions from all three surfaces into a unified Klatch project) would be a natural next step.

The specific alignment opportunity: Klatch's `projects` table already has `instructions` and `memory` fields. Claude.ai projects have a knowledge base. Cowork projects have project-scoped memory. Claude Code has CLAUDE.md. If Klatch can normalize these into a single model and import from any of them, it becomes the project portability layer the same way it's becoming the conversation portability layer.

**Sonnet 4.6 and the compaction API change the cost/capability equation.** Sonnet 4.6 at Sonnet 4.5 prices with 30-50% faster latency makes it viable as the default entity model for most use cases, reserving Opus 4.6 for complex reasoning tasks. The compaction API (server-side context summarization) could eliminate the need for client-side conversation truncation in long Klatch sessions. Both warrant immediate evaluation by Daedalus.

**Multi-agent patterns are maturing from experimental to production.** Code Review (multi-agent parallel analysis with cross-verification) and Agent Teams (coordinated parallel work with message passing) are now production systems at Anthropic. The architectural patterns they validate — dispatch, parallel work, cross-verify, synthesize — are directly applicable to Klatch roundtables.
