## HIGH RELEVANCE — Directly affects Klatch work in progress

### Claude Managed Agents launched April 8 — directly intersects Step 10

**What it is:** Anthropic's server-side agent harness with built-in tool execution, compaction, prompt caching, MCP server support, and persistent SSE streaming sessions. Beta header: `managed-agents-2026-04-01`. Pricing: $0.08/hour runtime + standard token costs.

**Why it matters for Klatch:** The Step 10 phasing plan (`docs/plans/STEP-10-EXPORT-META-MODEL.md`) explicitly identified Phase 5 (MCP server) as "deferred maybe." Calliope's April 10 futures memo (`docs/futures/2026-04-10-klatch-as-context-protocol.md`) reframes this: Managed Agents is the *infrastructure target* for Klatch's context interchange protocol vision. The Agents/Sessions/Environments model maps onto Klatch's entity/channel/project model. This isn't a coincidence — it's the same architectural shape Anthropic and Klatch independently arrived at.

**Verified Klatch impact:**
- Klatch already uses the same SSE event pattern Managed Agents uses, so the streaming bridge in `packages/server/src/claude/client.ts` is conceptually compatible
- Klatch's compaction path (line 522, beta header `compact-2026-01-12`) is already server-side, not client-side, so no breakage from the SDK deprecation (see item 3)
- Step 10 Phase 1 design should treat Managed Agents as a target consumer of the canonical package format from the start, not as a future migration target

**Action:** Daedalus should read the Managed Agents docs before Phase 1 design. The Phase 1 spec should be designed such that "serve this package over MCP to a Managed Agents session" is a first-class use case, even if the actual MCP server (Phase 5) ships later. I already raised this in my Step 10 questions memo today.

**Argus action:** None directly — this is design input for Daedalus. I'll write tests against whatever Phase 1 ships.

### Anthropic SDK 8 versions behind — needed for Step 10, not urgent for compaction

**What the automated scan said:** Klatch on `^0.78.0`, current is `^0.86.1`. Five releases between April 1–8. Key changes: structured `stop_details` (v0.82), client-side compaction helpers deprecated (v0.83), `claude-mythos-preview` model string (v0.84), Bedrock Mantle client (v0.85), Managed Agents SDK support (v0.86).

**What I verified:** Klatch uses `client.beta.messages.stream()` and `client.messages.stream()` directly. Neither is a client-side compaction helper — those would be wrappers around manual context summarization. Klatch's compaction path uses the server-side `compact_20260112` strategy via the `context_management` beta API, which is the *not-deprecated* approach. **The deprecation does not affect Klatch.**

**Real reasons to upgrade:**
1. **Required for Managed Agents access** — Step 10 will need it
2. **Defense-in-depth** — minor version drift creates compounding risk over time
3. **Mythos preview model string** — irrelevant since Mythos is invitation-only (item 6)

**Why not urgent:**
- Nothing is breaking today
- The streaming bridge in `claude/client.ts` is the only place that touches the SDK directly
- Semver minor bump should be safe but needs verification

**Action:** Daedalus should bump `^0.78.0` → `^0.86.1` before starting Step 10 Phase 2 (when MCP/Managed Agents integration becomes relevant). I'll write/update the test count after the bump and run the full streaming test suite to verify no regressions.

**Argus action:** Stand by to verify after Daedalus bumps.

## MEDIUM RELEVANCE — Worth tracking, not urgent

### Hono v4.12.12 security update — defense-in-depth, no active exposure

**What the automated scan said:** Five CVEs (path normalization, SSG path traversal, IPv4-mapped IPv6 bypass, cookie name validation, cookie prefix bypass). Klatch on `^4.6.0`, six minor versions behind. Flagged as High priority.

**What I verified:** Grep'd `packages/server/src` for `serveStatic`, `ssgParams`, `ip-restriction`, `setCookie`, `deleteCookie`. **None of the affected features are used in Klatch.** The route middleware path normalization fix is structurally relevant (it affects all Hono apps), but Klatch's routing is straightforward and doesn't rely on edge cases the fix addresses.

**Real reasons to upgrade:**
1. **Hygiene** — six minor versions of drift is more than I'd like
2. **Future-proofing** — if we ever add cookies (auth, session state), the patched validation matters
3. **It's a low-risk patch upgrade** — semver patch within minor, should be a no-op

**Why not High:**
- Zero active exposure today
- No deadline pressure
- Can be batched with the SDK bump in a single dependency-update session

**Action:** Daedalus should run `npm update hono` in the same session as the SDK bump. Both are low-risk, both are hygiene. No need to do them as separate efforts.

**Argus action:** Stand by to verify after Daedalus bumps. Run full server test suite.

## LOW RELEVANCE — Note and move on

### Vite 8 stable — Klatch is on Vite 6, larger jump than scan implied

**Automated scan said:** "Klatch's client uses Vite with no pinned major version constraint." This is incorrect. Klatch is on `vite: ^6.0.0` and `@vitejs/plugin-react: ^4.3.0`.

**Reality:** Vite 8 with Rolldown shipped in March; Klatch is two majors behind. The upgrade is `6 → 8`, not `7/8-beta → 8`. That's a larger jump that may surface breaking changes in plugin compatibility, build config, and the React plugin's Babel removal.

**Why low priority:**
- Klatch's current Vite setup works; no demand pressure
- Iris's frontend work hasn't surfaced any build performance complaints
- The Babel removal in `plugin-react` v6 is the main risk vector — needs an audit before upgrading

**Action:** No action this session. File for future. If Iris later wants faster build cycles or Vite 8-specific features (Rolldown, etc.), revisit then. Worth flagging to Iris that this is on the radar so she can speak up if it matters for her work.
