### 4. MCP SDK v2 — Stateless Protocol, Oct 6 Deadline Appears Incorrect

The MCP SDK v2 TypeScript package is out of beta. The v2 spec (dated 2026-07-28) makes the protocol **stateless by default** (initialize/initialized handshake removed, Mcp-Session-Id gone, capabilities travel per-request). Package splits into `@modelcontextprotocol/server` + `@modelcontextprotocol/client` + thin adapters (Node.js, Express, Hono, Fastify). The three deprecated subsystems (sampling, roots, logging) still function. **Critical correction:** the MCP blog post explicitly states v1 TypeScript receives bug fixes for "at least six months" post-v2 ship — the October 6, 2026 deadline cited in prior sweeps appears to have been incorrect or from a different artifact. The migration is still warranted but the timeline is less pressing.

**Source:** https://blog.modelcontextprotocol.io/posts/sdk-betas-2026-07-28/ | https://blog.agentailor.com/posts/mcp-v2-whats-changing-and-why
**Klatch impact:** Klatch uses `@modelcontextprotocol/sdk: "^1.29.0"` with StdioServerTransport. Migration to server-only split package is straightforward (no HTTP transport needed for Klatch 1.0). The stateless design in v2 is interesting context for any future HTTP MCP path. No immediate urgency, but migration should be planned.
**Prior mentions:** HIGH in `2026-08-03-sweep.md`; carry-over through 8/31 as "5 weeks to Oct 6." **Frame as: urgent deadline was incorrect — reprioritize as medium-term planned migration.**
**Verified against:** `packages/server/package.json:17 — "@modelcontextprotocol/sdk": "^1.29.0"` confirmed. `packages/server/src/mcp/bin.ts:18 — StdioServerTransport` (stdio only; stateless migration affects HTTP transports most).
