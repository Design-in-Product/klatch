### 2. MCP 2026-07-28 spec RC locked (May 21) — stateless protocol, MCP Apps, Tasks extension

The MCP steering committee locked the release candidate for the 2026-07-28 specification on May 21, 2026. Final spec publishes July 28; Tier 1 SDKs have a 10-week validation window to ship conformant support.

**Headline changes:**
- **Stateless protocol layer** — `Mcp-Session-Id` header and protocol-level sessions removed entirely. Any MCP request can land on any server instance; no sticky routing or shared session stores required at the protocol layer.
- **MCP Apps** — Servers can deliver interactive HTML interfaces rendered in sandboxed iframes. Tools declare UI templates ahead of time for host prefetch/cache/security-review; rendered UI communicates back via the existing JSON-RPC base protocol.
- **Tasks extension** — Moved from experimental core to extension; server answers `tools/call` with a task handle; client drives via `tasks/get`, `tasks/update`, `tasks/cancel`. `tasks/list` removed (unsafe without sessions).

**Source:** https://blog.modelcontextprotocol.io/posts/2026-07-28-release-candidate/
**Klatch impact:** Klatch's MCP server is stdio-only — `StdioServerTransport` at `packages/server/src/mcp/bin.ts:13`. The stateless change is architecturally significant for HTTP-based MCP deployments but does NOT affect Klatch's current stdio implementation. When `@modelcontextprotocol/sdk` ships a conformant Tier 1 update (expected within the 10-week window, i.e., by end of July), Klatch will need a dependency bump but likely no behavior change. MCP Apps is relevant to the "Klatch as universal context transport" Someday/Maybe (ROADMAP.md): an artifact canvas via MCP Apps is now spec-stable. Argus should verify what version of `@modelcontextprotocol/sdk` Klatch currently pins and whether an SDK bump is needed ahead of the July 28 GA.
**Prior mentions:** `docs/intel/2026-05-18-sweep.md` (stateless HTTP transport as SEP-in-review); `docs/briefs/cross-pollination/2026-04-09.md` (MCP Apps mentioned in sibling-project context). Frame as delta: SEP is now RC-locked with final-spec date; MCP Apps and Tasks are confirmed RC features, not just roadmap items.
**Verified against:** `packages/server/src/mcp/bin.ts:13` — `StdioServerTransport` confirmed. No HTTP MCP transport in current codebase.

### 5. Epicenter — convergent local-first app ecosystem (SQLite + plain text shared memory)

Epicenter is an open-source, local-first app ecosystem where every tool shares a single memory folder of plain text and SQLite files. Notes, transcripts, and chat histories from any Epicenter-compatible app are stored in a unified local store and accessible to all others. Gaining traction in the local-first/privacy-AI community in May 2026.

**Source:** https://toolradar.com/guides/best-ai-personal-assistants (surfaced in local-first AI search)
**Klatch impact:** Direct architectural parallel to Klatch's design philosophy (SQLite as source of truth, local-first, own your data). Klatch differentiates from Epicenter by being Claude-specific and by modeling entities and orchestration modes — Epicenter is a more generic file-level protocol. Worth a 15-minute scan of the Epicenter repo before Step 11 (Search) design: if Epicenter's cross-app memory format is standardized, Klatch could declare compatibility as a distribution/discovery story.
