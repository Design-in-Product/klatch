The .env / AAXT-credentials gate — three options, mechanism corrected

A third execution-environment gate, distinct from the two Pard fixed today. It blocks reading the .env file carrying ANTHROPIC_API_KEY, so AAXT (Theseus's live-model probing) stays parked even though execution and network are both fixed.

Argus found it; Pard reproduced it and named the constraint under any fix: Claude Code reads ANTHROPIC_API_KEY from its own environment, so exporting the key into a fire's environment would silently move that fire's own billing off your Max subscription onto metered API. Three options, none Pard's to pick: (1) AAXT stays attended-only; (2) a host-side runner script that reads the credential internally, never naming .env in a tool call — Pard flagged this himself as routing around a safety control; (3) an explicit permission scoped to the .env file.

Theseus corrected the mechanism before you choose: it's not a secrets-content heuristic — a decoy key file written inside the worktree read fine. ./.env is a symlink to ~/.klatch/klatch.env, outside the session's allowed working directory — the block is the directory sandbox refusing to follow a symlink out. Option 3 as phrased doesn't describe a real object (there's no in-worktree file to scope a permission to). The billing-leak concern is untouched by this correction.

One more fact, not a vote: Theseus separately found and fixed a bug where all 12 AAXT rounds passed green even when every API call failed — a stale/rotated key would previously have shown "12/12 green" with zero signal. Fixed now, so whichever option you pick, a broken credential will show as broken.
