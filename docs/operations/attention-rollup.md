### Truncated and refused messages — server half landed 8/12, client half is Iris's to finish
- **What:** `packages/server/src/claude/client.ts` treated any non-`tool_use` stop reason as a clean finish and wrote the message `'complete'`. The Anthropic SDK's actual union has four non-clean reasons — `max_tokens`, `model_context_window_exceeded`, `refusal`, `pause_turn` — and until this morning all four rendered identically to a normal reply. Found by Daedalus while reviewing the SDK changelog for a dependency bump, not while looking for it.
- **Iris's shape, landed by Daedalus (8/12, `03cfd01`):** `Message.status` gains `'incomplete'`; new `Message.stopReason` enum; `end_turn`/`stop_sequence` untouched. **One thing the spec hadn't anticipated, found while implementing:** the client updates its message optimistically on stream completion and never refetches (`App.tsx:103-107`), so without threading `stopReason` through `StreamEvent` too, an incomplete message would render clean until the user reloaded — the exact failure the fix set out to kill, just displaced by one page load. Added.
- **Two things fixed underneath, neither in the original ask:** the migration turned out not to be additive — SQLite's `CHECK` constraint on `messages.status` can't be altered in place, so every existing `klatch.db` (including the real 2,652-message one on Amber) would have thrown on the first truncated response rather than recording it; needed a full table rebuild, tested against a real legacy-shaped DB on disk. And history assembly filtered on `status === 'complete'`, which would have silently dropped truncated turns out of the prompt the model sees.
- **What's left, and it's Iris's surface, not Daedalus's:** `App.tsx`'s `handleStreamComplete` needs `status: event.stopReason ? 'incomplete' : 'complete'` threaded through — the type is already in `@klatch/shared`, this is the render branch.
- **Not proven yet, either half:** no live truncated response has been driven through end to end — every test mocks the SDK. Daedalus proposed one attended `max_tokens` send close both halves at once.
