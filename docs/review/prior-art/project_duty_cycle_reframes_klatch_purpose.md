xian's strategic reflection, 2026-05-28 (flagged as an ongoing strategic conversation between him and Calliope, not a closed decision):

**The duty cycle is close to solving some of the core challenges xian dreamed up Klatch to solve — but not all of them.**

- **Solved (or nearly) by the duty cycle:** mail delivery between agents, and agent collaboration. These were among Klatch's founding motivations. The cross-project duty-cycle methodology (file-based mail + autonomous drain + coordination cadence) now addresses them at the cohort level, *without* being a Klatch product feature.
- **NOT solved by the duty cycle:** **group conversation** — the synthetic klatch / roundtable, where multiple agents are brought into one room and the human sees a group chat while each agent experiences its own. This remains Klatch-unique.
- **NOT solved, and the emerging vision:** **Klatch as an interchange protocol** for context preservation across environments (the canonical package format + transports + MCP surface). This is where the strategic weight is shifting.

**Why this matters:** if a cross-project methodology (not a Klatch product) now covers mail-delivery + agent-collaboration, then Klatch's *unique, defensible* value narrows to the two things the duty cycle doesn't touch: group conversation (synthetic klatches) and the interchange protocol. This sharpens product/scoping decisions — invest where Klatch is uniquely needed, not where the duty cycle already delivers.

**Related principles xian stated the same day (D1/D4 of the dreaming-spike decisions):**
- **Thin proprietary layer.** "We may always be a superset, but whenever we can round-trip into another system with fidelity we should. Our proprietary layer should always be as thin as possible." Maximize fidelity round-trips; minimize lock-in surface.
- **Assembly-layer positioning** (D4, confirmed): don't compete on memory primitives (Anthropic ships those now via Dreaming); compete on conversation-as-substrate + cross-channel assembly. The interchange protocol is the expression of this.

**How to apply:** treat group-conversation UX (the composition gesture, synthetic-klatch experience) and the interchange-protocol work as Klatch's load-bearing differentiators in scoping conversations. When evaluating a feature, ask whether the duty cycle already covers it cross-project; if so, it's not where Klatch's unique value lives. This is a live strategic thread — revisit with xian, don't treat as settled. See also [[project_klatch_origin_and_vision]] and [[project_canonical_use_cases]].
