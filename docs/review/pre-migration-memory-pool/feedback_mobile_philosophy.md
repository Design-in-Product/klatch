No separate "mobile UX" treatment. Design holistically for users who are sometimes mobile, not for a mobile product.

**Why:** xian believes in a single coherent UX expressed appropriately in whatever context the user is in. "I don't believe in a 'mobile UX' so much as 'users who are mobile sometimes.'"

**How to apply:** When proposing responsive designs, frame as "how this design adapts to smaller viewports" not "the mobile version." Don't create separate mobile wireframes or flows — show how the same design system flexes. Progressive disclosure and information density are the tools, not separate layouts.
