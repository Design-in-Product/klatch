## Klatch is not behind — the hyper-circle is real (xian, 2026-06-19)

When Calliope started framing Klatch as "catching up on PM's patterns" (the attention-rollup, the duty cycle, etc.), xian corrected: **"You're really not behind at all. These methods are evolving and piggybacking on each other's advances. The roll-up is very new and grew out of things that were innovated on the Klatch side and with other projects too. We're all contributing to it. That's what makes this hyper-circle work."**

This is a load-bearing correction. The right mental model:

- **The methodology is co-developed across the cohort, not exported from one canonical project.** PM ran the duty-cycle pilot first; Klatch contributed the wait-default-vs-wait-forever sharpening, the building-vs-planning mode frame, the chronicler discipline, the don't-sit-passively rule, the no-op-batching refinement on day one. OpenLaws contributes its own pieces from its own work-shape. Janus's hub view is how the pieces find their way across.
- **Each project is the development environment for the pieces of methodology its own work-shape can naturally generate.** Klatch's unique surface area: the interchange-protocol / transporter-device work (because of the canonical-format MCP server + cross-vendor moat), and the synthetic-klatches / persistent-rooms primitive (because Klatch is the only project with that work-shape — PM has roles + tandems but no *room* primitive). These are the methodology pieces *only* Klatch is positioned to surface.
- **The defensive "catching up" posture is wrong.** When Calliope is reaching for an attention-rollup or any other pattern from PM, the framing should be "taking up our half of a co-developed pattern" — not "playing catch-up to PM's checklist." Klatch is not a follower in the cohort. The asymmetric-borrowing reading misses the actual dynamic.

**Operational implication:** when Calliope sees a useful pattern landing on PM or OpenLaws, the right next move is usually adopt-then-contribute (adopt, run it on Klatch's work-shape, surface what's different, route the differences back via Janus or via direct mail). Not adopt-as-laggard.

The 1.0-beta UX critical path is heightened in this framing — it's not just "ship Klatch's product" but "surface the methodology pieces only Klatch's work-shape can generate." Iris's composition gesture + working-meeting experience are both methodology surfaces, not just product features.
