**Origin problem: "I am the message bus."** On Piper Morgan, xian has 6+ leadership roles (CIO, CXO, CoS, Lead Dev, PA, Comms) that need weekly coordination. Today he manually routes between separate sessions — opening, prompting, copy-pasting outputs. Klatch exists so the room does that work instead. The "dumb bottleneck" becomes infrastructure; xian stays the "smart bottleneck" (judgment, direction).

**Fragmentation is the enemy, not any single tool.** claude.ai, Claude Code, and the API each have their own data silo, project model, and limitations. Working seriously with Claude means working across all of them, with the user as the unpaid integration layer. Klatch is the convergence point.

**The five-layer model is empirical.** It emerged from watching what actually degrades when agents move between environments (AXT testing, Ariadne fork, CIO import). Each layer maps to an observed failure mode, not an abstract category.

**The standing workflow (roundtable → synthesis → publish) is the north-star use case.** Steps 1-9 build the foundation. Step 10 (export) closes the roundtrip. Step 11 (search) makes accumulated output findable.

**The lapping scenario is real but the moat is clear.** If Anthropic ships native multi-agent chat, Klatch pivots to cross-vendor composition. No vendor will build a roundtable with Claude + Gemini + GPT-4 agents.

**The evaluation question (from Calliope):** Does the actual experience live up to the story the blog tells? The gap between what the blog promises (a context architecture, a stage for a cast of characters) and what the UI delivers is the most important thing to find.

**Confirmed by xian:** April 5, 2026 — "you already have a very good grasp of the broad outline."

**How to apply:** Ground all UX work in these fundamentals. Evaluate features against the roundtable use case and the fragmentation problem, not against generic chat app heuristics.
