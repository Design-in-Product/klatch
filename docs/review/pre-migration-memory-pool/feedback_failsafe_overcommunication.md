When a finding, process improvement, or methodology gap could matter at
both the project level (Klatch-local) and the hub level (cross-project,
Janus's domain), **route it to both layers.** Both as a failsafe.

**Why:** xian's stated 2026-05-10: "we need both project level sweeps
and hub level sweeps as a failsafe and we should err on the side of
over communicating." The principle is broader than sweeps — it's about
ecosystem reliability. A finding that one layer misses, the other
catches; a duplication is cheap, a gap is expensive.

**How to apply:**

- When framing a routing memo, ask "is this also relevant at the other
  layer?" — if yes, file at both. Don't pre-filter for "this is
  obviously project-local" or "Janus owns the hub side, skip the
  project version."
- Specifically for sweep methodology, intel cross-references, and
  process improvements: the cost of a redundant memo is low; the cost
  of a missed routing is high.
- Acceptable form is parallel memos with cross-references in each, or
  a single memo CC'd appropriately. Choose for clarity, not for
  brevity.
- Don't ask "should I send this to X?" if uncertain — just send it.
  The over-communication norm makes the question moot.

**Counter-pattern to avoid:** waiting for confirmation on routing
choices. xian's 5/10 framing makes this an explicit standing
preference; don't re-litigate per-memo.
