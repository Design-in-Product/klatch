## Decision (a): duplication with the agent's own disclosure prose — chip doesn't yield

Theseus's afternoon measurement: with `LOSSY_WINDOW_NOTICE` live, the model sometimes narrates the same
caveat in its own reply ("my slice of that thread is only the last 20 messages..."). Daedalus asked which
signal should yield if both fire on the same turn, explicitly declining to have a view himself.

Reasoned from the same evidence that motivated the chip's existence in the first place: the whole point of
building a platform-level signal was that a human can't be made to depend on an individual agent's
turn-by-turn judgment call to learn context was carried in (Corvus volunteered unprompted; Vesper declined
even under explicit authorization). The notice's own hedge is a *more reliable* version of that same
judgment-dependent channel, but it is still judgment-dependent — the model decides when the caveat is
relevant enough to say out loud. Conditioning the chip on the model's own text would recreate exactly the
dependency the original ruling removed, and would need content-sniffing the assistant's reply, which this
codebase doesn't do anywhere else and which is inherently fragile (paraphrase drift, model version changes).
Also checked whether the two signals are actually the same claim before calling it true duplication: they
aren't — chip asserts existence (count, always present when layer 6 fired); prose, when it appears, is a
specific epistemic hedge scoped to that reply's own uncertainty, prompted by a particular question. Decided:
chip stays unconditional. If overlap reads as noisy once this is live, the lever is the notice's wording
(Daedalus's), not chip suppression logic (mine).

## Decision (b): `hasOlderHistory` — not used to drive the chip

Daedalus flagged the trap explicitly: `omittedCount` reads 0 in exactly the case that matters (probe-3's
lost marking was never fetched, so the char-budget eviction counter never saw it), and `hasOlderHistory` is
the boolean that's actually true there. He asked whether I want either driving the chip now that both are
persisted and available with no backfill needed post-`6175bfd`.

Considered extending the chip to flag `hasOlderHistory` (something like "older messages not shown") as a
second application of the same "presentation must not imply a guarantee the mechanism doesn't provide"
principle, one layer deeper than room count — and decided against it for this increment. The original
chip decision had concrete evidence behind it (Corvus/Vesper's measured disclosure variance); this
extension would ship on inference alone, with nobody having demonstrated that a plain room-count chip
actually reads as an implied completeness guarantee to a real user. Daedalus's own caution — don't build a
count-shaped UI on a boolean — argues the same direction: adding a vaguer "not fully shown" clause without
being able to say how much isn't fully shown risks raising more questions than it answers. Gall's Law: ship
the smallest working increment, revisit when a real gap is shown, not preemptively. Both fields stay
available for that future fire.
