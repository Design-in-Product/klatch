### Strategy notes recorded for future rounds

The mix of source-pin + render-and-interact paid off. Specifically:

- **Source-pin** for pure structural pins (a class name, an error string, a guard conditional). Eliminates jsdom render cost, no hook-mock dependencies.
- **Render-and-interact** for behavioral contracts (button flip, click handler, conditional rendering).
- Use source-pin OR render — but rarely both. The exception (T1.7) was deliberate: source pins the class signature; render proves it lands.

Three iteration findings during the work:

1. **EntityManager + ChannelSidebar prop shapes** — both accept data as props from App.tsx, not via internal fetches. Initial tests mocked the API client unnecessarily.
2. **useModels hook breakage** — mocking `fetchModels` to return a bare `[]` corrupts the hook's data shape (it expects `ModelsResponse`). The clean fix is to reject the mock so the hook uses its `buildFallback()` path.
3. **Auto-selection in session browser** — `handleBrowseSessions` pre-selects all non-imported sessions, so initial state has Select-all disabled / Unselect-all enabled (opposite of intuition). Matched the claude.ai pattern exactly.
