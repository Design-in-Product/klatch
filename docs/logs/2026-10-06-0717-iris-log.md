**Built, smallest working increment:**
- **Server** (`entities.ts:224-240`): removed the `count <= 1` 400. An entity-less channel is now a
  legal response from this route, full stop — the client decides whether to also delete the channel,
  the server doesn't enforce consent. Flipped the two tests that pinned the old refusal
  (`entities.test.ts` "cannot remove the last entity (400)" → "allows removing the last entity, leaving
  it empty"; `round3-expansion.test.ts` "prevents removal of last entity via API" → "allows removal...,
  leaving it empty") rather than deleting them, since the behavior they pin is still load-bearing, just
  inverted.
- **Client, `ChannelSettings.tsx`**: removing an agent when it's the *only* one in the klatch now opens
  an inline branch — "X is the last agent in this klatch. Also delete the klatch, or leave it empty?" —
  with three explicit choices (Delete klatch / Leave empty / Cancel), styled to match the existing
  delete-channel danger-zone confirm already in the same file. This replaces the old `canRemove =
  channelEntities.length > 1` gate, which hid the remove button entirely with zero disclosure once down
  to one agent. Removing any *non-last* agent is unchanged — still instant, no prompt, since only the
  last-entity case has a destructive implication worth surfacing.
- **Client, `ChannelSidebar.tsx`**: an entity-less klatch now renders an "empty" badge in place of the
  agent-count badge, with muted/italic row styling instead of the normal secondary-text treatment. New
  sort key in `byLastActivity`: non-empty channels before empty ones, *then* by recency — so an
  abandoned empty klatch no longer competes on last-message timestamp with populated ones for position
  in its section. This is the "deprioritized in listings" half of the ruling; "flagged/greyed" is the
  badge + italic styling.
