## 07:30 — xian's UX observations (Session 5 → Session 6 closure)

xian shared his observations from testing. Three findings, in order of importance:

**1. Import is awkward and findable only in the footer grab bag.** Same problem as my Topic 2 (sidebar IA / footer grab bag) but sharpened: import is a first-class verb of the product, not a settings-adjacent action. It belongs to the import-to-export arc, not the footer. Visual weight should match its role.

**2. Import-as-modal is wrong; it should be a full-screen experience.** Claude Code session list at scale is unusable in a dialog — endless list of branch names with no real-project framing. Import/export aren't interruptions to chat; they ARE the work. Modal pattern signals "return to what you were doing"; correct pattern is "this is what you're doing right now."

**3. No actual way to compose a klatch from existing entities.** The product's core purpose — bring existing conversations into a room together — has no UI surface. Channel creation exists, entity creation exists, the composition gesture doesn't. This is the biggest gap and it lands directly on the entity reframe: when entities are creation-first abstractions, you create-then-assign; when entities are existing conversations promoted into roles, composition IS the central act and the current UI doesn't have it.

xian's framing: most of the rest is cosmetic, or about how context layers are captured/presented, or how the user is prompted (or not) during import/export. Walkthrough will surface those.

### What this sharpens

xian's observations confirm from the user side what my code-side evaluation pointed at. Mine were inferences about gaps; xian's are reports from trying to do the thing and being unable. Stronger evidence.

**The composition gap (#3) is the most important** — it's a capability gap, not a polish gap. The central job-to-be-done has no path through the UI. This is where the entity reframe most directly lands as a design opportunity, not just a mental-model shift.
