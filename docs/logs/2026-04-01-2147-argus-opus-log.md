## 22:00 — Round 13 Part A: Test Infrastructure Fixes

### A1. Root-level `npx vitest run` — FIXED

**Problem:** Running `npx vitest run` from repo root discovered tests in `.claude/worktrees/` (4 worktree copies × all tests = 496 phantom failures) and `dist/` (8 compiled JS dupes). Also, client tests ran in node environment instead of jsdom.

**Diagnosis:** Vitest v4 dropped auto-discovery of `vitest.workspace.ts`. The workspace file Daedalus recommended was never being read.

**Fix:** Created `vitest.config.ts` at repo root using vitest v4's `projects` field:
```ts
export default defineConfig({
  test: {
    projects: ['packages/server', 'packages/client'],
  },
});
```
This delegates to each package's own config, which sets the correct environment (node/jsdom) and `include` patterns. Worktrees and dist/ are excluded because the projects are scoped to `packages/`.

Also added explicit `include` and `exclude` to both package configs as defense-in-depth.

### A2. session-scanner.test.ts — FIXED

**Problem:** `scanExportedSessions(process.cwd())` in the import route scans `exports/sessions/` relative to cwd. When tests run from repo root (vs package dir), real session files leak into results.

**Fix:** Added mock for `scanExportedSessions` in the test file (returns null, matching "no exported sessions" behavior).

### A3. Kit briefing test assertions — FIXED

**Problem:** 4 tests in `kit-briefing.test.ts` and 1 in `project-instructions.test.ts` asserted old kit briefing text (`'do NOT have access to tools'`, `'conversation-only'`). Daedalus rewrote the briefing in Round 12 with MAXT F3+F4 fixes.

**Fix:** Updated assertions to match new text: `'do not currently have access to shell tools'`.

### A4. Client sidebar test — FIXED

**Fix:** Updated test assertion.
