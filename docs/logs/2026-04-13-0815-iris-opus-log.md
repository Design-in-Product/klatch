### Key findings (summary)

**Most critical issue:** Hover-hidden action buttons throughout the app (messages, entities, code blocks, project settings) break keyboard accessibility entirely. This is the #1 fix.

**Biggest Phase 3 insight:** The backend has rich layer-by-layer context data (via prompt-debug endpoint) that the UI barely exposes. The prompt layers display in channel settings reduces status strings like "ACTIVE — from project 'Piper Morgan' (3180 chars; 3 KB files)" to a colored dot. Phase 3 is fundamentally about surfacing this data visually — not building new features, but presenting existing data.

**Canonical use case assessment:** The roundtrip (import → structured work → export) is architecturally complete but experientially incomplete. The user can't see what context is assembled, can't preview what they're exporting, can't get a fidelity readout after import, and can't trigger an export from the UI at all.

**The blog gap (refined):** The blog promises transparency and context visibility. The backend delivers it. The UI doesn't surface it. Phase 3 is where this starts to close, but there are incremental wins available before Phase 3 (surfacing prompt-debug data in channel settings, adding import fidelity readouts).
