# Cross-Pollination Brief: Piper Morgan → Klatch

**Date:** 2026-03-20
**Source project:** Piper Morgan
**For:** Klatch team

## Key Insights

### 1. Capability Awareness Gap — Five Sources of Truth, Zero Coordination
**Relevance:** As Klatch entities gain capabilities via the roundtable system, entity prompts (layer 5) may describe capabilities the system can't actually execute.
**Source:** `dev/2026/03/20/2026-03-20-0618-lead-code-opus-log.md`
**Summary:** Smoke test revealed the LLM was offering capabilities that weren't registered in the dispatcher, creating implicit contracts the system couldn't fulfill. Five disconnected systems described Piper's capabilities; none were coordinated. Fix: gate all capability offers on the live dispatcher registry as single source of truth. 13 files modified, 5 new tests.
**Suggested action:** Consider early: where is the canonical list of what an entity can do? If entity prompts can diverge from actual system capabilities, users will hit the same implicit-contract problem.

### 2. AXT Two-Track Testing — Separating Plumbing from Perception
**Relevance:** Directly applicable to Klatch's prompt assembly verification.
**Source:** `dev/2026/03/20/` (Theseus session)
**Summary:** Theseus designed AAXT (Automated Agent Experience Testing) using synthetic context and deterministic assertions against the `prompt-debug` endpoint — no LLM calls. MAXT (Manual) uses real agents and qualitative interpretation. Key insight: separate what's mechanically verifiable from what requires human judgment. AAXT runs as a gate; MAXT only runs if plumbing checks pass.
**Suggested action:** Already being adopted. Validates the two-track approach.

### 3. Piper Alpha Planning — Convergent Agent-Persona Architecture
**Relevance:** Piper Alpha is a natural Klatch user — a persistent AI persona needing project context, conversation history, and multi-entity coordination.
**Source:** `mailboxes/ppm/inbox/memo-cio-piper-alpha-tasks-2026-03-20.md`
**Summary:** CIO launched planning for "Piper Alpha" — a Claude Code agent inhabiting the Piper Morgan persona as a working PM assistant. Three stakeholder memos delivered. Introduced "ceiling moments" (where structured capabilities are needed) vs. "path moments" (where conversational approach works).
**Suggested action:** The ceiling/path framing is useful for Klatch's entity model: some tasks need structured orchestration (roundtables, handoffs), others work fine as simple prompted conversations.

### 4. Omnibus Institutionalization — Process as Reusable Skill
**Relevance:** Pattern for preventing process drift across multi-agent teams.
**Source:** `.claude/skills/create-omnibus/SKILL.md`
**Summary:** Docs agent converted the omnibus log format into a formal `/create-omnibus` skill with a 9-step runbook. Locks down format, ensures consistent sourcing, prevents recurring problem of agents producing inconsistent outputs.
**Suggested action:** As Klatch agents accumulate recurring processes (release runbook, intelligence sweep, session wrap), consider formalizing as skills with explicit runbooks.

### 5. Reliability Incident — Force Push Destroys Demo Infrastructure
**Relevance:** Same structural pattern as Piper Morgan's Pattern-063 (Extension Without Integration).
**Source:** `docs/mail/calliope-to-argus-reliability-incident-2026-03-20.md`
**Summary:** Argus's session claimed demo work was complete, but a forced push during rebase recovery had silently destroyed the commits. Response: mandatory session-wrap verification (git log before claiming done, ls/cat to verify deliverables, never force push without PO approval).
**Suggested action:** Already addressed in CLAUDE.md. Root cause lesson: don't trust session logs that claim completion — verify against actual repo state.
