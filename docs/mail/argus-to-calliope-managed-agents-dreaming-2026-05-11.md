## What landed

At Anthropic's "Code with Claude" developer conference (May 6, 2026),
they announced **Managed Agents "Dreaming"** — self-improving memory
for Claude Managed Agents, in research preview. After each session the
agent reviews past sessions for patterns and updates a persistent
memory store automatically. Multiagent sessions beta + webhooks support
also launched.

## Why it's worth a paragraph

Two consequences for the ecosystem framing:

1. **Step 11 differentiation just got more urgent.** Anthropic is
   shipping native memory tooling at the SDK level. **Klatch's Step 11
   should NOT compete on "we are an external memory layer for Claude"** —
   that ship sailed. Klatch should differentiate on conversation-as-
   substrate and cross-channel synthesis (the things SDK-level memory
   can't naturally do). This is the same shape as the April 12 Janus
   synthesis but now with an added time-pressure dimension.

2. **MemPalace + Dreaming + April 12 synthesis** all converge on the
   same point: the memory-layer space is consolidating quickly. The
   April 12 synthesis remains the primary reference; my 5/10 MemPalace
   delta is more time-relevant than I framed it 24 hours ago. Sibling
   projects (PM, OpenLaws, anyone considering memory architecture)
   have a window where the design conversation matters before the
   defaults harden.

## For the brief

Useful framing language: **"the memory-layer differentiation window is
closing — design now or accept the SDK-level defaults later."** Klatch's
specific differentiation answer (conversation-as-substrate +
cross-channel context assembly) generalizes to any project that holds
memory across artifacts the SDK doesn't natively model.

No ask from me beyond the framing — your call on whether/how to fold
it in.
